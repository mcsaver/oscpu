# 12. 动手实验：把“看懂”变成“能证明”

这一章不再增加新的模块名，而是把前面学到的结构变成可以重复执行的观察任务。每个实验都遵循同一条证据链：

> 先提出一个周期级问题，再找到信号和状态，最后用波形、断言或计数证明答案。

这里故意不把“跑通仿真”当作唯一目标。只看到退出码为 0，并不能证明你理解了处理器；你需要能够解释某几个关键周期为什么这样变化，以及如果把一个 `ready` 拉低，哪些状态必须保持不动。

## 12.1 实验记录模板

建议每做一个实验，都保留下面这张表。它也是“一生一芯”式学习里很重要的一步：让结论能够被另一个人复核。

| 项目 | 需要记录的内容 |
| --- | --- |
| 问题 | 只写一个可以被证伪的问题 |
| RTL 范围 | 顶层到叶子模块的调用链 |
| 输入激励 | 指令序列、地址、异常或反压条件 |
| 观察信号 | `valid/ready`、tag、PC、ROB index、epoch 等 |
| 预期波形 | 动手前先画，不要看完波形再“解释” |
| 实际波形 | 给出周期号和关键值 |
| 结论 | PASS、FAIL 或 GAP |
| 反例 | 哪种输入可能推翻当前结论 |

`GAP` 不是失败。它表示当前证据只能证明较小范围，例如“静态 RTL 表明有保持逻辑，但还没有动态覆盖连续 20 周期反压”。

## 12.3 实验 1：RVC 跨包时，前端为什么不能猜

### 要回答的问题

当一个 32 位指令的前 16 位位于取指包末尾时，下一拍能否立即向译码级交付这条指令？

### 重点文件

### 激励设计

让 PC 的低位落在取指包末端，并放置一条跨包的 32 位指令。再分别制造：

1. 后继包立即返回；
2. 后继包被 I-Cache miss 延迟；

## 12.6 实验 4：Store-to-Load forwarding

### 要回答的问题

较年轻的 Load 命中较老 Store 的地址时，是从 Store Queue 转发，还是等待 Store 真正写入 Cache？

### 指令建议

```asm
sd x5, 0(x10)
ld x6, 0(x10)
```

随后逐步增加难度：

1. 同地址、同宽度；
2. 部分字节重叠；
3. 两个更老 Store 都覆盖部分字节；
4. Load 地址先算出，Store 地址后算出；
5. Store 或 Load 跨越数据字边界；
6. 地址翻译、权限检查或总线响应发生 fault。

### 重点文件

- [`OooStoreQueue.v`](../../../npc/rv64/vsrc/memory/OooStoreQueue.v)

- [`OooLsuAxiLaneAdapter.v`](../../../npc/rv64/vsrc/memory/OooLsuAxiLaneAdapter.v)

## 12.7 实验 5：浮点运算为什么看起来“晚很多拍”

### 要回答的问题

一条浮点指令的等待时间分别来自发射排队、寄存器读取、运算流水线、写回仲裁和退休中的哪一段？

### 指令建议

选择至少三类：

- 一条简单符号注入或搬运类；
- 一条加法或乘法；
- 一条除法或平方根。

### 重点文件

- [`OooFpIssueQueue.v`](../../../npc/rv64/vsrc/scheduling/OooFpIssueQueue.v)
- [`OooFpBackend.v`](../../../npc/rv64/vsrc/execute/OooFpBackend.v)
- [`OooFpArithGate.v`](../../../npc/rv64/vsrc/execute/OooFpArithGate.v)
- [`OooFpLongOpGate.v`](../../../npc/rv64/vsrc/execute/OooFpLongOpGate.v)
- [`OooFpDivIter.v`](../../../npc/rv64/vsrc/execute/OooFpDivIter.v)
- [`OooFpRegFile.v`](../../../npc/rv64/vsrc/regread_bypass/OooFpRegFile.v)

### 记录方式

对每条动态指令保存同一个 tag，并建立下表：

| 事件 | 周期 |
| --- | --- |
| dispatch |  |
| issue |  |
| operand read |  |
| execute accept |  |
| result valid |  |
| writeback accepted |  |
| ROB complete |  |
| retire |  |

两个相邻事件的周期差才是阶段延迟；`retire - dispatch` 不是单个功能单元的 latency。

### 反压实验

在结果有效时阻塞后级，检查：

```wavedrom
{
  "signal": [
    {"name": "clk",          "wave": "p......"},
    {"name": "fp_out_valid", "wave": "0.1..0."},
    {"name": "fp_out_ready", "wave": "0...1.."},
    {"name": "fp_tag",       "wave": "x.=..x.", "data": ["T9"]},
    {"name": "fp_result",    "wave": "x.=..x.", "data": ["R9"]},
    {"name": "fp_fire",      "wave": "0...10."}
  ],
  "head": {"text": "valid 等待 ready 时，tag、结果与异常元数据必须稳定"}
}
```

若 `valid=1 && ready=0` 期间 tag 或结果变化，说明接口违反了保持契约；不要用“最后结果碰巧正确”掩盖这个问题。

## 12.8 实验 6：精确异常与双退休边界

### 激励设计

1. 可正常完成的整数指令；

## 12.11 实验 9：每个 `vsrc` 文件都能找到自己的位置

第 11 章给出完整逐文件地图，本实验负责验证它不会随着 RTL 演进悄悄过期。

运行覆盖审计：

```bash
python3 docs/rv64core/study/tools/audit_vsrc_coverage.py
```

脚本检查三件事：

1. 当前 `npc/rv64/vsrc` 下的每个文件路径都至少在讲义中出现一次；
2. 每个 `wavedrom` 代码块都是严格 JSON；
3. 讲义中的本地 Markdown 链接能够解析到真实文件。

先按当前产品配置重新 elaboration 两个顶层，再生成当前源码清单：

```bash
docs/rv64core/study/tools/generate_elaboration_xml.sh

python3 docs/rv64core/study/tools/extract_vsrc_inventory.py \
  --top-xml /tmp/rv64-study-npctop.xml \
  --sim-xml /tmp/rv64-study-simtop.xml
```

XML 需要由当前 filelist 重新 elaboration 生成，不能长期复用旧文件。若没有 XML，工具仍可列出文件，但“顶层可达”分类不能作为证明。
`build_interactive_datasheet.py` 还会比较 NpcTop XML 与 RTL、Makefile、filelist 和产品默认
配置的 mtime；XML 较旧时会 fail-closed，提示先运行上面的脚本。

## 12.12 实验 10：给自己做一次口试

不看讲义，尝试用自己的话回答：

1. 为什么 `valid` 不能由 `ready` 组合地产生？
2. 为什么双发射重命名不是把单发射逻辑复制两份？
3. 为什么执行完成顺序不等于退休顺序？
4. 为什么 Store 可以先“执行完成”却晚得多才对外可见？
5. 为什么分支恢复不仅是修改 PC？
6. 为什么 IFU 旧响应要靠 discard 后继续 drain，而 LSU 还需要 token/epoch/ProducerId？
7. 为什么 AXI 的 `AW` 与 `W` 必须分别记账？
8. 为什么 FP pipeline 的模块级 latency 不等于指令端到端 latency？
9. 为什么同步异常必须在 ROB 头部精确呈现？
10. 为什么源码中的未实例化模块仍然需要在逐文件地图里注明？

如果某题只能回答一个名词，就回到对应章节，把答案补成“状态 + 周期 + 握手 + 反例”四部分。

## 12.13 学完之后，你应当能做什么

完成这些实验后，最低目标不是背出 150 个文件名，而是能够：

- 从任意一个接口信号向上找到生产者，向下找到消费者；
- 看到 `valid/ready` 就主动检查保持、丢失和重复消费；
- 看到 redirect/flush 就主动追踪身份代际和资源回收；
- 看到“完成”就区分功能单元完成、全局完成、ROB complete 和退休；
- 看到性能数字就追问配置、激励、测量边界和证据；
- 当讲义与 RTL 冲突时，以当前源码和可复核实验为准，并修正讲义。

这才是这套学习材料真正希望建立的能力：不是把框图记住，而是能够从框图进入周期，从周期进入状态，再从状态回到代码。
