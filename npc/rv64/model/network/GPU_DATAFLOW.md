# 以 always 行为为基础的 GPU CPU 模型

当前设计入口是直接描述 always 块。先保留行为和状态，再组合成模块、
模块网络与 CPU。电路综合、门级网表、AIG、LUT 和虚拟布尔处理器映射
都不是本路线的步骤或前提。先前文档中的电路映射路线已撤回。

现有实现入口见 [behavior/README.md](../behavior/README.md)。
目前已有行为 IR、语义解释器、生产模块描述与 I/O 连接层。相连的 LSU 完成路径
已通过 WSL Direct3D12 在 Intel Arc 130T 核显执行：三个源队列、六路轮转选择、
结果格式化与完成队列的内部反馈留在 GPU；两组参数共 2,400 周期、4,800 组完整
观察与生产 RTL 一致。新后端保留必要中间值并直接生成 uint32 运算，默认一个
256 线程组推进同一个模型实例。1,200 周期的 GPU 内核为 5.079 ms，C++ 参考循环
为 1.421 ms。详见 [连接网络结果](../behavior/TERMINAL.md)，尚无整核行为 GPU 的 CPI
或速度结论。先前独立模块结果保留在 [IGPU.md](../behavior/IGPU.md)。

## 基本单位

每个 always 行为块包含：

| 内容 | 用途 |
| --- | --- |
| 触发 | 哪个时钟边沿或组合输入变化使块需要执行 |
| 类型与读取集合 | 明确输入、旧状态、组合值及其位宽 |
| 有序语句 | 保留 if、赋值、局部计算和检查的位置 |
| 写入集合 | 明确写哪个状态及哪些位 |
| 提交规则 | 保持 NBA、局部阻塞赋值和源语句优先级 |
| 来源与层级 | 对应原 always 块，保留模块 I/O 和诊断位置 |

状态转移表达为 Block(old_state, inputs, settled_comb) → pending_writes。
多个同边沿块可独立产生 pending_writes，完成后按明确的写入归属统一提交。
不把一个块预先固定成一个宿主函数任务、一个 GPU 线程或一个 CUDA block。

组合 always 和连续赋值同样按行为描述。块内阻塞赋值按顺序立即生效；
块间组合依赖在相应边沿之前稳定。锁存、多时钟或完整事件区域行为需要
另外实现，不能把所有 always 都无条件当成“读旧状态、并行更新”的同步块。

## 构建顺序

1. 一个 always：表达条件、顺序赋值、局部变量与读旧值。
2. 多个 always：相同边沿读取共同快照，验证求值顺序无关性。
3. 一个模块：接入组合行为、状态保持、复位和 I/O。
4. 多个模块：根据实际 I/O 依赖连接，保留握手、取消和反压时序。
5. 整个 CPU：接入执行环境，与原 RTL 的退休/异常及终止周期对照。

真实 R64Counter 是第一段模块实现。它保留 22 个展开后的时序块和内部
进位缓存；生产 RTL 不变。描述是人工建立的行为程序，不是自动解析结果。
R64LsuRequestQueue 已接入宽位 payload、动态 packed 选择、取消、反压及原协议检查。
LSU 完成路径已连接多个真实模块，保留所有内部握手和反压。后续前端仍需读取
RTL 行为 AST，并逐项支持语句与类型。

## GPU 数据流约束

行为程序、状态和必要环境数据常驻设备；保持 Current、Pending/Next
和提交边界。相同或相似行为可以形成执行批次，但批处理不能改变块内顺序，
不能省略会影响未来周期的内部状态。

不从原 CPU 线程池继承函数组、dirty 原子通知、宿主屏障或固定阶段数量。
设备执行器消费行为规则。GPU 上的数据布局、局部存储与执行批次是后端选择，
不要求把原行为重新解释成电路布局或门级网络。

GPU 的同步范围仍需正确：块内屏障只解决块内依赖，跨块通信需要合法的
设备同步或执行图依赖。NBA 语义不等于任意线程可以无序写共享状态；
静态不相交写入和动态冲突必须分别处理。

同一块的最后一次重叠 NBA 决定该位更新。不同块若存在重叠写入，先明确
原 RTL 的行为是否确定；不能凭模型调度顺序添加优先级。当前基础表示拒绝
跨块重叠状态写入，并允许跨块静态不相交位片。

## 宿主与环境

宿主负责装载、粗粒度执行控制和检查记录。设备可在已知输入范围内连续
推进目标周期。未知外部输入必须在被消费之前形成精确停止点。

内存响应、总线队列、外设计时、反压状态等若会影响下一拍输入，需要加入
设备环境行为，或者在相应边界返回宿主。不能回放原 RTL 的响应来驱动新模型，
也不能因为一次设备执行包含多个周期而延迟本应发生的输入或中断。

DiffTest 的只读检查可以消费带时间戳的批量记录。输入反馈属于仿真环境，
必须按原周期处理。记录缓冲区用尽时暂停设备执行，不丢失记录，也不把宿主
等待时间添加到目标 CPU 周期。

## 验收

主要性能指标仍为单个 CPU、一个完整程序的端到端仿真时间；多实例吞吐另列。
精确性仍要求同镜像、输入、初始化与统计区间下，全部绝对退休/异常事件、
自然终止周期以及完整 DiffTest 一致。

现有 CPU 字级模型保留为参考工具。它的 38 个通过场景不转移为行为模型或
GPU 实现的通过结论。语义解释器、设备编译、实际 GPU 执行、整核 GPU 对照
分别报告，不能互相代替。

优化后的核显后端从行为规则直接生成 SIMD：小模型采用单 wave 寄存器状态和
wave 内交换；较宽模型按相似规则分 wave，共享当前状态，下一状态保存在各 lane
寄存器中，每个原生字只由一个 lane 提交。连接网络保留必要的组合中间值，按实际
依赖分批，避免无限内联和重复计算；不保存每个源块独立的候选缓冲区。
一次设备启动内推进多个边沿，CPU 不参与逐拍编排。CUDA 旧后端仍保留双缓冲方案。
当前覆盖适合单组的模块及已连接的 LSU 子系统，尚未解决整核跨组调度或设备环境。核显性能测量已报告，
不能将单模块相对旧 GPU 的加速迁移成整核或相对 Verilator 的加速结论。
