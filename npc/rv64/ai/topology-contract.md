# 网页架构设计的拓扑与量化约定

本约定服务用户选择的分工：网页 Pro 主导目标解释、根因假设、设计空间比较和微架构变换；
Codex 提供当前结构、源码和实验事实，完成实现与验证。它不建立新的批准 gate，也不保证某种模型必然得到更优方案。

## 什么是一颗可量化的设计单元

设计单元是一个有清晰状态归属、接收边沿、可见输出和取消/副作用合同的结构。组合子过程可作为该单元的子边标出。
一个文件可包含多个设计单元，一个单元也可以跨多个文件。ID 用于在图、源码与实验之间定位，允许方案把单元合并或拆开。

| 维度 | 必要事实 / 表达方式 |
|---|---|
| 位置与状态 | 稳定 ID、模块实例/源码、权威 Q 状态；副本是缓存、投影还是 owner |
| 数据边界 | 输入/输出 payload 和 tag 宽度；在哪个 valid && ready / grant 边沿建立所有权 |
| 容量 | 项数、端口/通道数、可并发 owner；区分集成参数、默认参数及可选支路 |
| 时序 | 同拍组合依赖、寄存边界、最早延迟与背压条件；不把队列深度当固定 latency |
| 吞吐 | 每拍最大真实接收/发出数、是否共享资源、initiation interval；未测填 UNKNOWN |
| 恢复 | reset、full flush、选择性 kill、undo、token/tag 复用、不可取消请求的 drain |
| 成本 | 逻辑状态位/选择宽度；mapped area / fanout / slew / slack 必须带测量范围，不由框图猜数 |
| 动态证据 | 有效窗口内的占用、阻塞条件、接收/完成数、latency 分布；重叠计数不得当互斥停顿相加 |
| 未知项 | 标出 UNKNOWN，并给最便宜的区分性观察方法；不是要求补齐全部数据才允许设计 |

全核保留四类图或边：数据、资格与信用、取消与恢复、不可撤销副作用。每条关键边说明源/目标 ID、
信号/owner、组合或寄存、真实接收条件与反压方向。只画 IF/ID/EX/MEM/WB 或模块方框不足以描述乱序事务生命周期。

## Codex 发给网页端的材料

1. 简短任务：用户目标、当前基线、硬约束、可观察验收和当前开放问题。不给本地首选架构。
2. 全核与各域的当前拓扑、单元表和源码定位。旧实验必须标日期和当前是否采用。
3. 实测事实：最差路径及邻近端点族、内部 Q 起点路径、对应时钟/库/输入延迟；动态周期、已知延迟和 UNKNOWN。
4. 足够核查合同的源码附件；网页不能访问的本地路径不能作为唯一证据。缺少的源码可以按网页请求补发。
5. 已失败实验用简短事实呈现，包含联合改动范围和实测结果；不把失败解释强加为最终根因。

优先上传可检索文本（含 Mermaid 原码、表格、来源和编号源码片段），图像可补充阅读但不作为唯一合同。
附件是当前快照；源码改变后重新导出，并明确旧测量是否仍适用。不要上传全量 build、标准单元库或无关私密文件。

## 网页端应交付的设计变更

网页负责提出并比较少量完整候选，而非仅审查 Codex 提出的候选。每个候选可用下表表达，必要时附修改后的图或伪 RTL。

| 项目 | 输出 |
|---|---|
| 结构变换 | 涉及的单元 ID、要切断/新增的依赖边、状态迁移和新寄存边界 |
| 周期合同 | latency / initiation interval / capacity / credit 在改动前后的值或可证伪假设 |
| 正确性 | 同拍 kill+response、背压、tag 复用、精确异常、store 与不可撤销外部事务如何处理 |
| 收益解释 | 预期改善什么可观察指标；数值是测量、估计还是上界；为什么不只是移动瓶颈 |
| 代价与边界 | 下游 mux、fanout、恢复周期、面积/时序、额外状态和代表负载的风险 |
| 最小完整实验 | 哪些变更必须一起做，哪些可以独立消融；最有判别力的用例与保留/淘汰条件 |

以上是帮助直接实施的表达方式，不要求为每次小修填表。源码前提错误由 Codex 用证据纠正；
若纠正改变架构取舍，返还网页端决策。Codex 不盲目照抄，也不在执行时暗中替换已选择的主要架构。

网页返回的修改图与周期合同先作为候选保存在该轮目录；只有本地实现并验证后，才更新生产拓扑。
当前结构与拟议结构不能混写在同一张“现状”图中。

## 结果回传

回传相同设计点的功能、周期、关键机制和输入/输出/相邻路径测量；区分已有结果、新测、失败与未运行。
网页根据结果调整结构；本地按已约定条件直接保留或回滚。不把新增观察工具、文件数或成功上传称为性能提升。
