四、时序部分：在原事件边界预编码发布，而不是寄存已经产生的 flush
4.1 新寄存位的精确定义

要求每个复位后的可达周期满足：

systemverilog
publish_q ==
    event_valid_q &&
    (!event_trap_q || event_prepared_q);

因此：

systemverilog
full_flush_o = !rst_i && publish_q;

与当前接口同拍等价。

禁止写成：

systemverilog
publish_q <= full_flush_o;  // 错误：这是把全清延后一拍

附件给出的事件更新优先级是：先处理原事件的 flush/prepare，再由 exception、interrupt、非白名单 serial capture 按顺序覆盖。按照这份完整更新式，可以直接实现：

systemverilog
wire new_trap_event =
    capture_exception || capture_interrupt;

wire new_nontrap_event =
    serial_commit_o && !scratch_read_w;

// CTL-05：与原 event_* 寄存器在同一边沿更新。
// trap_prepare_o 仍使用原定义和原事件状态。
always_ff @(posedge clk_i) begin
    if (rst_i)
        publish_q <= 1'b0;
    else if (new_trap_event)
        publish_q <= 1'b0;
    else
        publish_q <= new_nontrap_event || trap_prepare_o;
end

assign full_flush_o = !rst_i && publish_q;

这个简化式来自附件中的实际赋值优先级，不是对“典型 trap 流程”的猜测。

rv64-measurements

我对上述三个事件状态位、三个 capture 条件及 reset 的 128 组布尔组合核对了原 next-state 与简化式，结果一致。这只是对附件状态方程的组合核对，不是新 RTL 的形式证明、仿真或 STA。

其周期合同如下：

事件	原实现	R3
捕获 exception/interrupt 的边沿	建立未 prepared 的 trap event，不发布 flush	同边沿 publish_q=0
trap prepare 的边沿	event_prepared_q 置位，随后该周期发布 flush	同边沿 publish_q=1，同周期发布
非白名单 serial event 捕获	随后该周期发布非 trap flush	同边沿 publish_q=1
flush 被处理的边沿	清事件；没有新捕获时不再发布	同边沿 publish_q=0
reset	同步清事件、组合接口静默	保持；新增位同步清零

原 effect_allow、stop_birth、trap target、serial commit、不可撤销事务检查均不重定义。

4.2 全清和 partial cancel 在 LSU 接收侧分开

BE-09 保留现有 canonical kill 输出供未修改消费者使用，另导出不含 full flush 的 partial 取消信息。抽象合同为：

systemverilog
canonical_kill[slot] ==
    full_flush_o || partial_cancel_only[slot];

partial_cancel_only 必须从已验证 plan、pending 和当前恢复谓词直接生成，不能实现成：

systemverilog
partial_cancel_only = canonical_kill & ~full_flush_o;

后者在布尔值上可能对，却没有移除原来的组合依赖。

对 LSU 中某个已持有 owner：

systemverilog
deny_owner =
    rst_i ||
    publish_q ||
    partial_cancel_only[owner_tag[ROB_W-1:0]];

live_owner = raw_owner_valid && !deny_owner;

原有 sticky dead、完整 tag 匹配、head 授权等额外条件继续保留。PREPARED_CANCEL 版本也必须分离全清与 partial 部分，并继续逐拍对照 canonical 取消集合。

实施范围不是只有 CQ：要覆盖 LSU-01 的相关 owner 更新、LSU-05/06 的 query/physical 资格，以及 LSU-07/08 的完成资格。否则只是把原全清又从某个中间 cancel_candidates 接回去。

不改以下合同：

外部响应 ready 仍由原 raw Q 信用或已登记 dead owner 决定，不加入当前 kill 的组合反馈。
mem_issued、effect 仍只由原真实物理握手建立。
head 授权、A/D replay、已接受外部请求的 drain 和 pin 释放边沿不变。
所有同步 reset 检查和原 SDC 保留。
4.3 这部分的收益边界

它针对的是 B 中多个消费者共有的取消前缀，不是修补 C 特有的 effect 尾段。B 的 effect、RR 历史与 CQ payload 都有相应证据；而 C 的 effect 额外退化主要发生在 mem_ready→capture D，不能拿那个结果证明本方案已经会改善 ready 后逻辑。

本方案不会消除全部 flush→CQ payload 路径。front/skid 的合法移动和有效性仍受取消控制。目标是缩短广播生成和重复资格选择，而不是把必要取消从时序图中删掉。

五、性能部分：CQ 中的确值可以早用，完成权限仍留在原 WB/ROB 边界
5.1 本轮只覆盖一个明确集合

首轮启用范围为：

已完整形成结果、成功、对齐、普通 RAM、非 atomic/IO、副作用类、非异常，并且写非零 GPR 的 load。

符合相同条件的 full-forward load 可以覆盖；FP load、异常、IO、LR/SC/AMO、非对齐慢路径默认不走这条 early 路径。

这是实际值已存在后的提前使用，不是预测 cache hit，也不是按预计返回拍数唤醒。

5.2 目的凭据从 birth 获取，不能在 LSQ 释放后回读

新增 sideband：

systemverilog
typedef struct packed {
    logic       value_ok;   // 完整结果形成后才允许置位
    logic       rd_write;
    logic       rd_fp;
    logic [5:0] pdst;
} load_value_ticket_t;      // 9 bit

状态归属和转移：

**BE-02→LSU-01：**MEM reserve 与原子 birth 同边沿登记 pdst/rd_write/rd_fp，共 8 bit。这里保存的是该指令的物理目的身份，不是新 Rename 真源。
**LSU-01→LSU-06：**真实响应进入 raw，或 full-forward 结果被 terminal 接收时，随同一完整 tag 带走凭据；在完整结果资格已知后生成 value_ok。
**响应直入 CQ：**保留现有空 raw 旁路；ticket 必须与同一个 response token、tag、最终结果一起参与当前 event 选择。
**LSU-07→LSU-08：**ticket 使用与 tag/result 同一组 first/second winner、物理 lane 分配和写入条件。
fault 来源的 value_ok=0，无需为本轮 early 功能携带有意义的目的凭据。

当前 load 会在 raw/CQ 或 full-forward terminal 捕获后释放原 LSQ，因此不能在 CQ 输出时再用旧 LSQ slot 查询 pdst。

5.4 IQ 与 RR 的具体变化

**BE-04：**从当前两路常规 WB＋两路 ALU early，扩展为再加两路 CQ early。新增命中加入原有 ready 初始化和驻留唤醒逻辑，保持原取消与 birth 优先级。

尤其必须覆盖 DEFER_READY：不能只给旧 IQ entry 发一次脉冲，漏掉刚 birth、下一拍才初始化 ready 的消费者。当前 ALU 已有相应的早唤醒/完成唤醒配合，新增路径必须保持同等级合同。

    else
        snapshot_value = prf_value;

这是逻辑合同，不是要求绕过当前 read-plan/compact/rank 实现。实际实现必须把 hit、实际 data、必要的身份/rank 信息在原快照边沿一起保存。

禁止只登记“来自 CQ lane0”，下一拍再读取已经换 head 的 lane0。输出受阻时使用原 ingress/terminal 的数据保持能力，不增加一级隐藏旁路寄存。

5.5 数据持续可得的合同

一个已经用 CQ wake 唤醒的、仍存活的消费者，在其读边沿必须满足以下三种情况之一：

生产者所处位置	读值来源
仍驻留 CQ front	新 CQ bypass
已被 CQ pop、进入 WB 捕获/接受窗口	原 WB 转发路径
已完成正常 WB	PRF

CQ pop 必须与原 WB 捕获同边沿发生。数据从 CQ 转到 WB/PRF 后，不能出现“消费者 ready 已置位，但值已无处可取”的空窗。

取消生产者时，更年轻依赖消费者必须按原恢复合同取消；early 事件不能绕过 IQ、RR、EX 的最终存活检查。出现 load fault 的结果从来没有 value_ok，因此不需要为本方案增加消费者 replay。

**CQ 的值被消费者读过，不释放 CQ owner，也不算 load 完成。**该 load 仍必须沿原 WB/ROB 路径完成一次。

5.6 条件化周期合同

以下以一个响应在 E0 被空 CQ 捕获为例，且消费者已经在 IQ、其他源 ready、没有发射资源争用。

事件	B	R3
响应接受、CQ 捕获	E0	E0
从 CQ front 产生并采样 early wake	无	E1
原 WB 结果捕获	E1	E1
原 WB/ROB 正常接受	E2	E2
消费者源 ready 更新	E2	E1
消费者 issue	E3	E2
RR 读值快照	E4	E3

**其中响应→CQ=0、响应→WB 接受=2 是已有定向实测；消费者边沿和 WB 内部捕获位置是根据拓扑推导、待源码/短测核对的合同。**如果现有 Issue 把本拍 wake 直接用于组合选择，绝对边沿需要相应调整，不能照表伪造测量；本方案要求验证的是相对提前。

在该无争用条件下，目标是消费者提前一拍 issue/read。WB 背压时可能提前更多，因为 load 仍可在 CQ front 提供真实值。反之，skid 中的 load 不提前暴露；它成为 front 之前不承诺收益。

按上述字段直接实现，新增 payload 小计为：

LSQ：20×8＝160 bit。
raw、full-forward、CQ：各四条×9，共 108 bit。
CTL 发布位：1 bit。

合计 269 bit 声明状态，不含可能变化的 RR rank/控制位。它不是面积预测。IQ 还会增加最多 16×3×2 组源比较位置，ROB/RR 也增加相关组合负载；这些可能比新增 FF 更影响时序。

七、必须保持的边界与定向反例
边界	R3 必须满足的合同
同拍 kill＋物理 response	原 ready、真实 response fire、raw/CQ 转移和 dead drain 不变；被取消 owner 不生成 cq_value_valid。
kill front、skid 晋升	ticket 与 tag/result 使用同一移动条件；不能把旧 front 的 pdst 配上新 front 的值。
CQ→WB 交接且消费者正在读	本拍取 CQ 或既有 WB 数据，跨边沿后取 WB/PRF；不存在值空窗。
WB 长时间背压	CQ head 继续持有真实值，early 不依赖 out_ready；不能因 wake 已发出而 pop。
birth 与 early/正常 WB 相邻	覆盖 early 同拍 birth、次拍 DEFER_READY、CQ pop 后 birth 等情况，不能永久漏唤醒。
tag/slot/preg 复用	继续使用完整 tag、真实 short-owner 校验及原 reuse_block；新增凭据不是放宽复用的许可证。
reset	原接口静默、同步清除保持；空槽残留 payload/ticket 不得形成 wake。
store B、错误、pin、A/D	全部沿原合同；不把 AW/W、prepared、query 接收或 cache hit 解释为真实成功 B。

对于同一 live preg 同时命中多个合法 bypass 来源，应断言身份一致且值一致；不同 live owner 不得仅因 preg 编号相同而被合并。

为什么不重复上一轮失败联合方案

不过，CQ value64 多接到 RR 本身会增加负载，所以“不增加选择级”也不是 CQ→WB 不退化的证明。此前 C 的教训仍然适用：输入、输出、相邻族和完整程序必须一起裁决。

十、交给 Codex 的最小完整实验与保留条件
最小完整实现

冻结一个 R3 双开关均开启的新设计点，包含：

同拍 publish Q＋LSU 全清/partial 分离；目的凭据全程同 owner 携带；两路 CQ short-owner 授权；IQ 初始化/驻留唤醒；RR 实际值快照与 CQ→WB→PRF 连续性。

缺少最后两项的“只提前发 wake”不是本方案；缺少 effect/query 等使用侧改接的“只换 CQ flush 输入”也不是完整物理方案。

两个开关用于小范围反证：

只开发布重编码：同输入下，原接口 fire、取消集合、owner 更新及短程序周期应保持一致。
只开值旁路：验证消费者提前和数据连续性，区分它与控制重编码的影响。

不要求先为三个候选各跑一轮完整综合和双基准。先完成定向及整核短测，再对一个完整 R3 做完整程序与原约束 SystemTop STA。联合版不达标时，不把未经独立完整验证的半个方案摘回主树。

有判别力的新增观察

沿用已有 response→CQ→WB 记录，只补真实 full-tag 关联的：

CQ 首次合资格 front → early wake → 依赖消费者 issue → RR 实际取值边沿/来源。

短测必须覆盖连续依赖 load、WB 长背压、两 CQ lane、skid 晋升、kill+response、kill+交接、DEFER_READY 相邻 birth，以及 ROB slot/preg 复用。原 store B-error、Sv39、Sdtrig、非对齐、FP、取消和全系统 NEMU 回归仍然保留。

我给本轮设定的工程保留门槛

这些是实验裁决标准，不是已经预测能够兑现的数字：

维度	保留要求
正确性	原断言、定向反例、完整 DiffTest 通过；没有提前副作用、漏完成、重复完成或错误唤醒
完整周期	两个固定完整基准均不增加，至少一个降低 0.5%；退休数、输出和工作量按原口径核对
机制	在符合条件的依赖短测中，消费者确实提前；不能仅凭 CQ early 计数增加
Setup	同约束完整 SystemTop 全局 WNS 改善至少 0.10 ns，setup TNS 不恶化
Hold	WNS/TNS 不恶化，负 hold 端点不新增；逐语义核对，不能只看最差一个值

约束身份	原库、真实数组、reset 输入延迟、uncertainty、时序例外保持；仍未过 1 ns 就继续标 FAIL

面积照实报告，不拿新增 269 bit 声明状态去估计面积，也不使用 cycles×(1 ns−WNS) 计算运行时间。

本轮执行结论：从 B 实施 R3，不复活 C，不扩大 CQ/WB 选择网络，不改变物理接受和真实 B 完成边界。核心交付是让已存在的 load 确值更早驱动有用执行，同时把共同取消资格的生成移回已有事件边界；是否值得保留，由上述同一个完整设计点的周期、机制和整核时序共同裁决。
