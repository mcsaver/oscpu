## 实测结论与归因边界

- 同语义 event_before_q[0] 的 setup slack 从 -2.119304419 ns 改善至 -1.483735442 ns（+635.568977 ps）；effect_q[14] 从 -2.020954609 ns 退化至 -2.164543390 ns（-143.588781 ps）。
- effect_q[14] 两版实际最坏路径都经过 cancel_candidates[15] → forward_query.out_valid[0] → mem_valid[0] → mem_ready[0]。到 mem_ready 的累计 arrival 只增加 4.049301 ps，而 mem_ready → capture D 的尾段增加 149.746418 ps。该对应端点的实测退化主要位于事务接受后的状态更新段，不能把它归为取消传播段变慢。
- B 的 effect 族本身已经接近全局最差：effect_q[1] 为 -2.109362364 ns，距 B global worst 仅 9.942055 ps。20/20 个 effect 与 5/5 个 RR 历史状态的各自最坏 max 路径都由 reset 经 full_flush 启动。因此 effect 并非 C 才存在的全新问题，但 C 的额外退化位置也不能代表 B 应优先改哪一段。
