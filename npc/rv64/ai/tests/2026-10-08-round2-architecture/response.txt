四、首选方案的最小完整合同

以下名称是拟议接口语义，不假定源码已有同名端口。

4.1 三个事件必须严格区分
概念	含义	能否释放live源owner
candidate_present	当前有一份可供路由的数据记录	不能
reserved	按寄存信用为候选预定当拍接收位置	不能
capture	数据、完整tag及元数据真实进入CQ有效owner	可以，按原交接合同

另有独立的cancel/drain终结路径。取消终结不是一次成功完成传输。

取消前候选必须来自真实旧状态或真实响应握手，不能通过把当前event_valid中的某个名字替换成cancel_candidates来得到。已给出的cancel_candidates仍含flush依赖，不适合作为取消无关信号。

4.2 响应资格分成“可以路由”与“可以成为owner”

对空raw的成功load，概念上拆成：

systemverilog
// 真实总线握手；ready合同保持基线。
bus_fire = mem_rsp_valid && mem_rsp_ready;

// 现有语义，不改变其live判定。
raw_fire = bus_fire
        && alive_q[token]
        && !killed_now(token);

// 仅用于候选路由；不得含本拍flush/kill。
rsp_candidate = RESPONSE_BYPASS
             && bus_fire
             && alive_q[token]
             && !raw_occupied_q
             && !rsp_error
             && eligible_from_protected_descriptor;

// 只有最终真实捕获，才算bypass成功。
bypass_fire = selected_as_response && cq_capture;

raw_enqueue = raw_fire && !bypass_fire;

这里的eligible_from_protected_descriptor仍是原来的成功、对齐、普通RAM load资格，不扩大类别。

必须保持以下边界：

响应token仍然只是受生命周期保护的LSQ slot。 在真实捕获边沿，从该slot的受保护descriptor取得完整ROB tag，并与result及异常元数据一起捕获。不能假定外部响应突然携带了完整tag。

raw lane已有寄存占用时，选择原raw记录；不能因为它本拍被kill，就把它当成“旧状态为空”并塞入新的response bypass。

mem_rsp_ready继续只使用原寄存信用或原已登记dead-load drain条件，不引入CQ/WB当前组合反馈。

未赢仲裁、没有CQ信用的live响应仍然回退raw。被取消或已死亡token的响应按原drain处理，不能因为预写了数据就建立CQ owner。

4.3 六源仲裁先选候选，再判断是否真实接收

每个源提供：

纯文本
candidate_present
candidate_payload
candidate_full_tag
semantic_live_now

前三项的数据选择锥不能依赖本拍取消。semantic_live_now承接该源完整的现有存活资格。

RR根据候选集合选第一、第二候选；宽tag/result按这两个候选选择。CQ信用和rank到physical lane的映射都由Q态决定。

然后才产生：

systemverilog
capture_rank[r] =
    selected_present[r]
 && structural_credit_q[r]
 && selected_semantic_live_now[r]
 && !rst
 && !flush;

event_grant只由真实capture_rank反向映射产生。RR状态只根据真实捕获更新；预定但取消、空位预写、独立dead drain都不当作成功grant。

不能在发现第一候选被kill之后，把第二候选重新挤到第一位置。 那会把kill重新接回宽数据选择链。

以向量顺序{rank1, rank0}为例：

寄存信用	第一候选	第二候选	实际接收mask	行为
11	live	live	11	正常双捕获
11	killed	live	10	第二份保持原物理落点，不压缩
11	live	killed	01	第一份正常捕获
01	killed	live	00	本拍不重新分配第一位置；live源保持或回退raw

最后一行是明确接受的机制代价。不能一边要求kill完全不影响路由，一边又要求零代价地把kill空出的当拍位置重新分配。

CQ因此必须接受稀疏有效mask，而不再要求真实接收只出现00/01/11。信用仍可以是prefix；输入有效性不必是prefix。

4.4 CQ每lane改为两个固定物理槽

每lane保留两份完整payload/tag存储，增加或重组织：

纯文本
occupied_q[2]
head_q
payload_q[2]

不增加CQ深度。head_q指向该lane最老的有效owner。

输入落点只看旧状态空槽，不看本拍pop、kill或flush。

systemverilog
slot_credit = 存在Q态空槽;
target_slot = 由Q态占用和head确定的空槽;

// 允许对无owner空槽预写；不会覆盖任何现存owner。
payload_write[s] = slot_credit && (s == target_slot);

payload写使能不使用最终capture，也不使用本拍kill。空位中的预写值没有任何完成语义。

旧owner的终结和新owner建立分别处理：

systemverilog
drop[s] = occupied_q[s]
       && (entry_killed_now[s]
           || ((s == head_q) && actual_wb_accept));

survive = occupied_q & ~drop;
occupied_d = survive;

if (input_capture)
    occupied_d[target_slot] = 1'b1;

if (rst || flush)
    occupied_d = '0;

头指针优先指向仍存活的旧head，其次旧的另一个owner，最后才是本拍新捕获的owner。

由此得到以下合同：

持有稳定。 一个live输出owner在没有真实WB接受、也没有被取消时，payload和完整tag不变，不跨lane、不跨物理槽迁移。

单占用同拍替换。 旧head出队，同时新输入写入另一空槽；边沿后头指针指向新槽，不新增流水泡。

双占用出队。 只切换头指针，不把back宽数据搬进front寄存器。

旧状态满时不借用本拍释放信用。 即使本拍pop或kill，也不进行组合信用返还。这与当前free=~back_q的保守信用思想一致，不新增CQ→源→CQ回路。

部分kill可以清除任意槽。 清除back不移动仍被背压的head；清除head时，边沿后指向幸存的另一个owner。

需要正视的物理代价是：固定槽方案在CQ输出增加了槽选择mux。原输入路径可能缩短，但CQ→WB可能变差；这必须进入本轮全局STA验收。

4.5 取消不延迟，副作用不提前

本拍取消仍须阻止：

纯文本
新的CQ有效owner成立；
被取消CQ结果的PRF写入；
由该结果产生的有效唤醒/旁路；
ROB完成或异常记录写入。

不能只依靠“边沿后CQ valid会清零”来阻止同一边沿的写回。

CQ输出request继续允许作为提前需求提示，但只有VALID、真实接受和正确owner资格共同成立，才允许产生写回效果。必须检查PRF写与ROB接受的共同资格：ROB拒绝旧tag，并不自动证明PRF没有被旧结果误写。

全局flush保持现有语义：取消所有现存LSU语义owner，不保留较老owner。部分kill仍按原年龄与tag保护规则处理。

已经存在的外部总线义务、晚响应接收与drain规则保持；清除内部完成owner不等于撤销一个已经进入真实总线生命周期的事务。

4.6 错误、reuse与守恒

错误响应不进入成功load快速资格，继续原raw/fault路径。所有fault payload与普通结果一样携带完整tag，被取消的fault不能向新复用owner上报异常。

store许可、真实写接受、B响应、成功B后cache更新，以及异常退休规则全部保持。本轮不改变任何store能否对外执行的判断。

reuse保护不因“payload已预写”而提前结束。释放LSQ slot只能依据原真实mem_end、取消和drain合同。CQ捕获之后自行持有完整tag，不再回查一个可能复用的LSQ descriptor来补全身份。
