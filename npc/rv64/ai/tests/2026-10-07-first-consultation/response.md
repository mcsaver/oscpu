## 1. 结论与证据边界

**工程投入优先级：先选“小窗口下的关键依赖链、完成通路与恢复控制联合整形”，暂不先扩窗口/MLP；哪种方案最终性能更优，仍属证据不足。** 这不是重复已有提前唤醒、descriptor 同拍准备或 LSU 提前申请 WB。

本审查仅依据题给材料，未访问仓库、重跑测试或修改 RTL。历史联合修改降低完整程序 cycles 3.46%/4.53%，说明准备/完成等待**曾经**值得优化；不能把联合收益分摊给单项，更不能当作当前剩余收益。历史 IQ16→32 的微小收益只削弱“单扩 IQ”，不否定协调改变 ROB/PRF/LSU 的方案。（题给历史对比、`backend/TOPOLOGY.md`）

**最危险的错误前提，是把“队列满/head 未完成”当作根因，甚至当成可回收周期。** 队列满可能是长延迟传播的结果，也可能阻止独立工作进入，现有占比不能区分。单读慢路径 owner 也不等于全核 MLP=1：受限 hit-under-miss 和 store B 重叠已经存在。B owner 驻留更不等于退休关键路径上的 B 等待。（题给源码摘要、held-ready）

另一项硬约束是时钟可实现性：历史 setup/hold 均 FAIL，最差路径穿过恢复→访存绑定→LSQ。不能只比较 CPI，也不能由该 prelayout WNS 宣称真实 Fmax。现有数据不足以判断依赖 load、读 miss、store 响应、翻译屏障或分支恢复各自限制了多少有效进展。

## 2. 两个完整候选

### A：保留容量，重整关键链与控制边界——首选

固定现有 ROB/IQ/LSQ/PRF 容量，按“操作数可用→合法发射→响应接收→完成发布”检查剩余气泡。仅对证实暴露的环节引入有界完成暂存、仲裁调整或流水重排；两个 WB 捕获口不盲目扩宽。完成源须保持数据、tag、异常和有效性直到实际捕获；提前授权不能冒充完成，唤醒必须与数据确实可用一致。

恢复方向是尝试分离“按年龄边界立即禁止失效操作获得新授权”和“逐项回收”，隔离 flush→绑定的大组合路径；仍保持每拍至多两项 youngest-first 回滚、正确映射恢复以及分配/退休暂停。中间态可能因新增寄存拍增加 load-use 或恢复延迟，必须同时验证 cycles 与时序，而非只看某条路径变短。

### B：协调扩大窗口与多事务 RAM 读——有条件保留

扩大 ROB 时同步核算 PRF、LSQ、IQ/读口、翻译请求与完成缓冲，而非只改深度。Dcache 增加有限的逐事务 owner/MSHR，明确同线合并、bank/set 冲突、回填和 AXI 响应路由；仅允许已满足翻译、属性、顺序条件的 RAM load 并行。信用分层管理且响应始终有落点，不能让年轻读耗尽 head 或必要翻译的前进资源。store、IO、atomic 不借此放松许可。

只先扩容量而未打通上述通路，可能增加的只是等待项、选择扇入、恢复清扫量及错误路径流量；先加 MSHR 却没有独立合法请求，也可能只增加面积。这些中间态的退步不能直接否定完整 B，但必须解释其资源瓶颈为何会在下一阶段消失。

**两者共同的合同：** 用指令序号、分配代际和事务映射贯穿翻译/LSQ/cache/WB，不能仅凭复用后的槽号接收晚到结果。未对外承诺的内部请求可取消；已经承担的 AXI 握手与响应义务必须完成，事务 owner/信用不能因 ROB 撤销立即释放，被杀 load 不得再写 PRF/ROB。普通 store 仍须 head/effect permission，等待真实请求接受及 B 响应；成功 B 后才更新驻留行，错误按现有精确异常路径传播。**store buffer 至多先作暂存，不自动赋予提前退休资格。**（题给 `R64Lsu.v` 与 Dcache 合同）

## 3. 按价值排序的下一步行动

1. **建立真实头阻塞账本，成本最低。**  
   区分“本地准备/完成链拖延”与“等待必要服务”。先核对测量版本和配置；使用已有波形，否则在不改 RTL 的原生配置中重跑并采集必要信号，保留 DiffTest/assert。跟踪首个不能退休项及其依赖祖先，记录合法就绪、请求接受、响应、WB、load 消费者可发射及恢复时刻；多重阻挡条件保留，不强拆因果比例。若候选交接点没有出现在暴露等待链上，否定它对所测区间的解释；缺信号则不能归因。历史 profile 多一拍的边界单独处理。

2. **做“窗口×读事务数”的受约束诊断，成本低至中，无 RTL 改造。**  
   区分“容量不足”与“读 owner 不足”。用真实依赖/访存轨迹比较小/大窗口×单/多读事务，保留 PRF/LSQ/WB 信用、地址依赖、翻译屏障、响应和副作用约束；回放中已知的地址不能提前变成可发请求。观察扩大窗口是否提供独立合法 miss，以及它们是否覆盖头关键等待，并检查结论对下游服务能力的敏感性。若机会只在删除上述约束后出现，否定该 B 配置的依据。正确路径回放至多是乐观诊断，模型 cycles 不作 RTL 收益。

3. **审计恢复—绑定—LSQ 时序锥，成本为分析加同约束综合。**  
   区分“主要是控制扇出”与“存储/选择结构本身太深”。检查实际单元、扇出、到达时间和约束，并确认历史最差路径是否仍存在。若当前瓶颈已转移，撤销对旧时序锥的优先改造；即使 setup 路径缩短，也不能跳过 hold 或宣称最终频率。

4. **另获授权后才做单假设 RTL 试点，成本最高。**  
   区分“局部等待减少”与“端到端有效进展增加”。A 只实现账本命中的一个完整交接合同；B 必须同时提供有限多 owner 与足够信用，不能以裸扩队列代替。观察完整程序 cycles、正确性、资源和同约束 STA。若只改善 ALU 热窗口，或靠省略错误、取消、响应取得收益，淘汰该实现；若只是把等待转移到另一环节而无端到端改善，停止继续堆资源。

## 4. 首轮实验与裁决

**选择行动 1：不改 RTL 的“暴露交接等待—独立读候选”配对账本。** 两个程序各选预先固定、按提交数界定的窗口，不挑最好看的片段。用既有可导出信号同时记录：

- **H：** 头关键链已满足安全条件，却仍等待本地交接/WB。
- **M：** 当前已驻留的独立 RAM 读具备发射资格，仅被慢路径 owner/事务信用挡住；另记 hit/miss 与 bank/set 条件，不能把所有受阻读都叫 MLP 机会。

H、M 可以重叠，不能相加，更不是可节省 cycles。

**继续：** H 反复出现，且能指出一个尚未实现、合同完整的安全缩短办法，继续该 A 试点。  
**淘汰：** H 为零，或相应等待已被现有旁路覆盖，淘汰该交接假设对所测窗口的解释，不外推为否定整个短延迟方向。  
**证据不足：** 无法验证依赖关系、发射资格或取消/异常条件，不能据相关计数选方案。

**当前裁决：证据不足；工程顺序仍是先测 A，保留 B，不宣称新增性能收益。** 若 H 很少，而独立 miss 候选反复伴随关键读等待，且受约束诊断显示扩窗能持续提供更多合法独立 miss、实际下游可并行、物理代价可承受，我会改选 B。当前窗口没有 M，不能否定窗口外机会。若主要暴露的是无法被有效工作覆盖的真实 store B 服务等待，则两者都应降级，转查真实写响应服务路径，而不是用提前退休隐藏它。
