# RV64 乱序核重构

本任务借鉴用户在 `npc/rv-cpu/vsrc/IFU/ifu.v` 中的简洁代码风格。
用户澄清：不要求照搬队列或重定向方案，也不限定五级流水线；具体微架构由实现者选择。
重点是在整体架构构思时就考虑每周期指令推进能力，避免完整代码堆积后再补性能。

## 当前目标与历史任务

2026-09-05 用户明确废弃此前 RV64 待优化任务及优化方向。本重构是新的工作主线。
历史 BPU/FP/PPA sweep、candidate、next-action、阶段编号和待办不再决定本次实现顺序；
既有源码、测试和实测结果保留作为参考。历史测试 PASS 不作为重构后 PASS。
NPU 等任务外的用户改动保持原样。

## 实现原则

- 保留 RV64 乱序执行与按程序序提交；借鉴五级流水线的清晰职责划分。
- 每个请求明确接受事件、有效载荷、唯一状态持有者、完成事件和取消规则。
- 请求被外部接口接受后必须完成或排空；flush 只撤销年轻指令的架构可见结果。
- ROB 与物理寄存器映射负责投机状态；CSR、异常与访存副作用在合法提交边界生效。
- 消除不可达的历史旁路和常量传输，避免叠加兼容壳与重复状态。
- 保留当前 ISA、AXI、DiffTest 和顶层集成契约；参考 IFU 的 32-bit PC、16 深度及
  2-bit epoch 不是 RV64 核的固定参数。

## 验收

重构后的生产 filelist 对应同一套 RTL，依次完成：

1. 相关定向测试、全量模块仿真和实际全核编译。
2. 全部适用的非 OS 核级仿真：AM、官方 ISA/特权测试、基准及已有相关系统场景。
3. 仿真通过后综合，报告配置、单元/面积、真实警告与未覆盖的物理边界。

OS 启动不在本任务范围。综合与 STA 各自按实际运行结果报告，不能相互代替。
本文记录目标，不代表任何验收项已完成。

## 性能、面积与时序预算

理想无停顿稳态的目标是 IPC=2、CPI=0.5。冷启动、分支恢复、数据依赖、
缓存未命中和外部总线延迟分别计入实际程序 CPI；不得用单元发射率替代整核提交率。
保留四个整数寄存器读口与双提交的总体预算，先重构资源调度，容量扩张需有收益证据。

| 模块 | 构思时的预算与边界 | 本轮实现/验证状态 |
| --- | --- | --- |
| 取指、解码、派遣 | 热缓存下每拍提供两条；握手反压不丢包，预测错误可恢复 | 收窄生产 fetch sequencer 的状态/接口；其余前端继续重构 |
| 重命名、ROB、PRF | 双分配/双提交、同拍 RAW/WAW 正确；保留精确异常 | 正在审视实际资源与调度耦合 |
| INT/MEM 调度 | 两个逻辑年龄域共享最多两次源读取；访存内部保持保守程序序 | 正在实现；避免用扩窗掩盖结构瓶颈 |
| 整数 ALU | 两条固定延迟通路；避免重复加法器和左右移位网络 | 共享加减比较与移位网络，64 位结果等价证明通过 |
| 乘法器 | 一份完全流水的整数乘法器，II=1；高位有符号修正不串入部分积生成 | 四个 32×32 部分积、交叉项归并流水，连续请求及全部整数 M 操作验证通过 |
| 除法器 | 变延迟、独立占用；前导零处理按商有效位减少迭代 | radix-4、每拍两位商、独立符号修正；异常边界/随机/取消验证通过 |
| 乘除完成 | 多在途乘法与除法独立持有身份；反压期间结果稳定，取消后身份不提前复用 | 预留 credit、结果队列及完整 producer live mask 已集成 |
| 浮点执行 | 区分算术吞吐与长延迟操作；检查写回冲突和舍入/异常，不以黑盒隐藏面积 | 尚待本轮模块评估与重构 |
| LSU、缓存、MMU | 地址生成与后续等待解耦；真实 PA 上检查别名、转发、PMP/PMA；AMO/device 精确授权 | 调度/持有资源重构进行中，其余模块尚待本轮评估 |
| AXI | AR/R 与 AW/W/B 独立生命周期；写数据顺序、反压稳定、错误汇总和 flush 排空完整 | 仲裁器与 lane adapter 已支持读写重叠并通过定向 A/B |
| CSR、异常、提交 | 一个 CSR 权限表，主访问与探测同源；架构状态只在精确边界改变 | CSR 读端改并行地址选择，known/writable 合并，定向测试通过 |

时序目标保持当前工程的 500 MHz（2 ns）、icsprout55 约束；不通过降低频率目标制造通过。
组合深度、比较器扇出、宽数据选择、寄存器读写端口和队列搬移网络均在设计时考虑。
综合后按实际标准单元、SRAM 宏和完整浮点/BPU 的模型边界分别报告面积与时序，
不能把占位黑盒的零面积/零延迟作为整核结果。目前尚无本次重构的综合或 STA 结果。

## 当前直接证据

- 真实 NpcCoreTop 理想整数流水：8 个由固定程序 PC 确定的窗口，每窗口 64 拍；
  合计 512 拍、1024 条提交，每拍均双提交。逐条检查 PC、指令及目的寄存器值。
  这证明热缓存独立整数场景的稳态 CPI=0.5；包含冷启动和循环边界的整个测试
  为 2294 拍、2216 条提交，二者口径不同。
- 乘除定向测试接受 2215 条请求，正常完成 2212 条，另外 3 条由 kill/flush 撤销；
  覆盖 word/XLEN、有符号/无符号、高半乘积、除零/溢出、反压及 ROB 环回。
- AXI 同一测试的旧/新结构对比：写响应延迟 0/2/5 拍时，另一 lane 的读地址
  接受延迟由 2/4/7 拍降至 1/1/1 拍；原写事务终结时间均为 1/3/6 拍。
- 首次集成的既有 115 项模块回归通过。之后的新增测试和 RTL 修改继续单独验证，
  最终仍须对完整最终 RTL 重跑必要的集成回归。
- 旧核与首次集成均运行官方 177 项 ISA/特权用例；176 项通过，唯一失败为
  rv64mi-p-breakpoint。该核当前未实现可选 Sdtrig，现有 CSR 单元测试明确检查
  trigger CSR 非法；不能通过合法 no-op 假装支持硬件触发器。用户已确认保留现有 ISA，本例明确列为不适用，不能计入 PASS。

## 参考方案

- [BOOM execution stages](https://github.com/riscv-boom/riscv-boom/blob/master/docs/sections/execution-stages.rst)
  与 [issue units](https://docs.boom-core.org/en/latest/sections/issue-units.html)：
  按执行能力与可用性调度，并明确流水/非流水单元、旁路与写回竞争。
- [Rocket Multiplier.scala](https://github.com/chipsalliance/rocket-chip/blob/master/src/main/scala/rocket/Multiplier.scala)：
  流水乘法与可变迭代除法分工，除法早退参考操作数的有效位差。
- [CVA6 serdiv.sv](https://github.com/openhwgroup/cva6/blob/master/core/serdiv.sv)：
  迭代除法中的规格化、符号和提前结束边界。
- [PULP AXI crossbar](https://github.com/pulp-platform/axi/blob/master/doc/axi_xbar.md)：
  通道切分、事务数量、ID 路由与写通道顺序必须端到端一致。
- [RISC-V Sdtrig](https://github.com/riscv/riscv-debug-spec/blob/main/Sdtrig.adoc)：
  未实现 trigger 时 CSR 可报非法；宣称实现该扩展必须具有真实触发器。
